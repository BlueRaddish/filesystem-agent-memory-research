# Agent memory: preserving evidence, maintaining state, and onboarding a fresh agent

Public research search cutoff: **2026-10-08 UTC**. This is a **structured scoping review**, not an exhaustive systematic review or an independent reproduction of published experiments. It uses twenty selected primary sources spanning early LLM memory architectures, conversation benchmarks, temporal memory, filesystem experiments, and recent diagnostic and systems studies. Selection favors mechanisms relevant to accurate retention and continuation of work. Paper methods, evaluation sections, and limitations were inspected selectively; the [source catalog](../sources/agent-memory.json) records review depth and publication status. No private conversation corpus informs these conclusions.

The central design question is whether an unfamiliar agent can recover the important context needed to act correctly. Token reduction is a secondary constraint. A short memory that loses a correction, exception, or unfinished obligation fails this objective even when it produces fluent answers. Conversely, preserving every byte does not establish that an agent can find, interpret, or apply the evidence. The literature supports separating these problems, but does not establish a universally best memory architecture.

## Distinguish the records an agent needs

For this project, the following are operational categories, not claims that a machine implements human cognition:

| Record | What it should answer | Typical failure |
| --- | --- | --- |
| Episodic evidence | What was said, observed, attempted, or verified, and when? | Losing the original qualification or source |
| Semantic knowledge | What reusable fact or concept follows from the evidence? | Treating an extraction or inference as an observation |
| Current state | What is authoritative now, including active constraints and unresolved work? | Applying a superseded rule |
| Procedural memory | What method worked, under which conditions? | Reusing a lesson outside its tested setting |
| Working context | What does this particular action need to consider? | Omitting one necessary dependency |

A transcript, a current-state brief, and a reusable procedure serve different retrieval questions. Their relationship should be explicit. A filesystem can host all of them; its directory structure alone does not provide that relationship or determine which statement is authoritative.

## What the early architectures established

**Generative Agents** records natural-language experiences and retrieves through relevance, recency, and importance. Reflection derives higher-level statements with pointers to supporting memories; planning and reflections re-enter the memory stream. Ablations associate these components with more believable behavior, while reported errors include failed retrieval and fabricated embellishment. Its short simulated-world evaluation addresses behavioral coherence, not months of project continuity. The reusable lesson is a distinction between observations and derived reflections with traceable support. [AM01](https://arxiv.org/html/2304.03442v2)

**MemoryBank** combines timestamped conversations, daily/global event summaries, evolving user portraits, dense retrieval, and optional forgetting/reinforcement inspired by the Ebbinghaus curve. Its companion-oriented evaluation includes generated user dialogues and qualitative examples. This establishes a concrete multi-level organization, but does not validate personality deductions as facts or forgetting as desirable for dependable project work. **Inference:** access frequency and age can influence retrieval priority without authorizing deletion of important evidence. [AM02](https://arxiv.org/html/2305.10250v3)

**MemGPT** separates an editable working block, rolling conversation queue, recall storage, and archival storage. Function calls move information into context; warnings and queue flushing manage overflow while original messages remain in recall storage. Multi-session recall and document experiments show the utility of this orchestration. Its results also depend on the underlying model's tool use, and agents sometimes stop paging before finding relevant evidence. Persistence and an available search interface therefore do not guarantee successful recall. [AM03](https://arxiv.org/html/2310.08560v2)

**Reflexion** stores verbal reflections on feedback in an episodic buffer for subsequent attempts, rather than updating model weights. Evaluations cover decision-making, reasoning, and coding. This is primarily memory for improvement across trials, rather than a comprehensive record of current project state. **Inference:** a reusable lesson should retain the attempted action, feedback, conditions, and verification outcome; an agent's explanation of failure should remain distinguishable from the externally observed failure. [AM04](https://arxiv.org/html/2303.11366v4)

Together, these architectures introduce several separable decisions: what to preserve, what to derive, what to keep continuously visible, when to retrieve, and how to revise memory. Their evaluations do not justify replacing full evidence with one recursively rewritten summary.

## Granularity and retrieval matter independently of storage

**SeCom** explicitly compares turn, session, and summary memory. Turns can fragment a request across separately retrieved pieces; sessions can mix topics; summaries can discard details. It segments dialogue into topical units and uses compression for retrieval denoising while supplying original retrieved segments to response generation. Experiments on LoCoMo and Long-MT-Bench+ support the approach within those configurations. Its main LoCoMo experiment uses generated QA pairs; official QA evaluation appears in an appendix. This is especially relevant to completeness: a compact search representation can point to richer source material without becoming the only surviving record. Segmentation quality and task distribution remain dependencies. [AM07](https://arxiv.org/html/2502.05589v3)

**ReadAgent** similarly retains a route back from gist memory to original passages. It paginates documents into episodes, creates gists, and performs interactive lookups for details. Tests use long-document comprehension tasks rather than evolving conversation state. Its relevance is architectural: overview and navigation need not sacrifice recoverability. Whether a fresh agent recognizes when a gist is insufficient remains a separate question. [AM11](https://arxiv.org/html/2402.09727v2)

**A-MEM** constructs notes with content, contextual descriptions, keywords, tags, timestamps, and embeddings, then generates links and evolves neighboring notes as new memories arrive. LoCoMo evaluations and ablations associate linking and evolution with improved performance. This makes organization an active process, but generated associations and revisions depend on the base model. **Inference:** preserve original note content and a revision trail; treat contextual descriptions and links as derived navigation aids unless their assertions are separately supported. [AM08](https://arxiv.org/html/2502.12110v4)

A controlled **ACL 2026 analysis of graph and non-graph memory** decomposes systems into keys, evidence values, queries, index structures, retrieval, and answering. Experiments on LongMemEval and HaluMem find that implementation details substantially affect results; graph advantages depend on construction and retrieval settings, and unsuitable settings can degrade performance. Its framework and tested configurations are not exhaustive. It nevertheless undermines choosing a graph merely because graph-based products report strong aggregate scores. Compare components under matched conditions. [AM20](https://aclanthology.org/2026.acl-long.1232.pdf)

## Updates should preserve the difference between history and authority

**Mem0** extracts salient facts and selects ADD, UPDATE, DELETE, or NOOP after comparing candidate facts with similar existing memories. Its graph variant marks obsolete relationships invalid rather than physically removing them. The authors' LoCoMo study compares several memory and retrieval approaches. This is a vendor-authored paper: reported efficiency and accuracy are findings for its protocol, not independent certification of production readiness. Salience extraction and conflict resolution can lose material before retrieval begins. [AM09](https://arxiv.org/html/2504.19413v1)

**Zep/Graphiti** distinguishes raw episodes, semantic entities/relationships, and community summaries. It models event time separately from ingestion time and tracks validity of changing relationships. Source links can trace semantic artifacts to episodes, although the paper explicitly says those links are not directly examined in its experiments. DMR and LongMemEval results are vendor-authored. The architecture offers useful provenance and temporal mechanisms; it does not prove lossless extraction merely because the episode store retains raw input. [AM10](https://arxiv.org/html/2501.13956v1)

**THEANINE** retains old memories and links temporal and cause-effect relationships, retrieving timelines rather than removing outdated entries. Its TeaFarm evaluation introduces counterfactual challenges to responses grounded in past conversations. This highlights why obsolete facts may explain an evolution rather than constitute disposable noise. A generated causal link still requires scrutiny, and preserving history must be paired with correctly identifying the currently valid state. [AM12](https://aclanthology.org/2025.naacl-long.435/)

**APEX-MEM** uses an entity/event property graph, append-only event storage, and multi-tool retrieval that resolves evolving or conflicting information at query time. Its ACL 2026 paper evaluates conversational QA and reports construction expense, extraction/entity-resolution risks, ontology limits, and sensitivity to the reader's structured tool use. It supports postponing irreversible consolidation, but append-only extracted events are not automatically a complete transcript. **Inference:** pair current-state projections with retrievable evidence and explicit supersession relationships. [AM16](https://aclanthology.org/2026.acl-long.749.pdf)

## Filesystem memory is a medium and a maintenance policy

Anthropic's **memory tool documentation** specifies client-side persistent file operations, directory inspection at task start, and writes that survive context resets. The application controls storage and path validation. This is an official interface description, not an empirical evaluation of memory fidelity. It shows that plain files can be a native memory interface, while leaving organization, provenance, concurrency, and quality policies to the application. [AM17](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)

The **Filesystem-Based Memory** July 2026 preprint separates management, search, and execution roles and varies store organization, tools, scale, and model strength across conversation and embodied-task settings. Its central finding is limited: organization improves search economy on large material, but the measured agents do not convert organization itself into better conversational answers; store organization often erodes with growth. Harness changes also reshape the store. This argues for evaluating maintenance and information preservation, rather than using attractive directory trees as evidence of better memory. Generalization beyond the tested agents and workloads remains open. [AM13](https://arxiv.org/html/2607.26637v1)

The September revision of **Agent Memory: Characterization and System Implications** profiles construction, retrieval, and generation separately across representative systems. Inter-session workloads expose a freshness/latency tradeoff: asynchronous construction can serve a query before preceding writes commit. Benchmark and hardware configurations bound the results. **Inference:** a handoff should identify both the latest committed evidence and the latest incorporated summary/index; a fast retrieval from a stale projection can miss the most important recent correction. [AM15](https://arxiv.org/html/2606.06448v2)

## Evaluate retention, retrieval, interpretation, and continuation separately

**LoCoMo**, published at ACL 2024, uses persona/event-grounded generated conversations checked and edited by humans. Its benchmark includes QA, event summarization, and multimodal dialogue generation. The released conversations are long, but the corpus is small and constructed rather than a sample of real project handoffs. Later papers frequently use the QA component only. Results on that component do not establish success on the entire benchmark or on tool-driven continuation. [AM05](https://aclanthology.org/2024.acl-long.747.pdf)

**LongMemEval**, published at ICLR 2025, tests extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention. It supplies evidence annotations and scalable history variants and studies indexing/retrieval/reading choices, including session decomposition, fact-augmented keys, and time-aware query expansion. It is stronger than a single static fact lookup, but still evaluates questions over prepared histories. It does not by itself test continuous write integrity, concurrent agents, or whether a successor completes unfinished work. [AM06](https://arxiv.org/html/2410.10813v2)

**AMemGym**, accepted to ICLR 2026, addresses static off-policy evaluation with interactive simulated users whose profiles and evolving states are grounded in structured data. The assistant's own choices affect subsequent interaction, enabling evaluation of memory-driven personalization. This increases diagnostic realism while introducing simulator/schema assumptions; it is not direct evidence from human collaboration or repository maintenance. [AM19](https://arxiv.org/html/2603.01966v1)

**LongMemEval-V2**, a May 2026 preprint, moves to multimodal web-agent trajectories and questions about static state, dynamic state, workflows, gotchas, and deployment-specific premises. A fixed reader consumes gathered evidence. AgentRunbook-C stores raw trajectories, workflow documents, manifests, and inspection scripts and uses a coding agent to gather context. Its relevance to fresh-agent onboarding is unusually direct, but its context-gathering QA formulation does not test actual resumed task execution, and coding-agent retrieval carries substantial latency. [AM18](https://arxiv.org/html/2605.12493v1)

**EvalMem**, a September 2026 preprint marked accepted to EMNLP 2026 Findings, diagnoses whether facts were encoded, retrieved by the native system, and usable by a generator supplied oracle evidence. Its store examiner uses source evidence as a diagnostic search aid. This is privileged evaluation information, not a deployable retriever receiving only an ordinary query. The study finds retrieval the most frequently attributed failure layer across its tested systems; attribution still depends on annotation, examiner accuracy, and observable stores. [AM14](https://arxiv.org/html/2609.22231v1)

These benchmarks answer different questions. A retrieval recall score, an LLM-judged QA score, a behavioral believability rating, and task success are not interchangeable. Numeric rankings also depend on corpus version, answer categories, base models, prompts, evidence budget, retrieval settings, and judge. This review therefore does not reproduce headline scores or pool them into a leaderboard.

## Practical design implications — hypotheses to test

The following are project design inferences, not findings from an experiment conducted here:

1. **Keep recoverable evidence beside useful projections.** Use chronological episodes for what happened; a current-state brief for what governs action; and indexed topics/procedures for navigation. Each derived claim should identify source records and the transformation that produced it. Summaries can be regenerated when an extraction is disputed.
2. **Make corrections explicit.** Record the revised claim, what it supersedes, effective time when known, recording time, scope, and why authority changed. Distinguish a user correction from an agent hypothesis, a tool result, or an unexecuted proposal. Preserve ambiguity rather than choosing a convenient interpretation silently.
3. **Give a fresh agent an entry point with obligations.** The entry point should expose active goals, constraints, decisions, verified results, unresolved questions, next actions, and links to supporting material. It should state its coverage and last incorporated evidence. The important comparison is whether the successor avoids material mistakes, not how small the file becomes.
4. **Retrieve enough connected evidence.** Search exact identifiers and phrases as well as semantic paraphrases; follow topic and temporal links; inspect the original segments supporting a summary. Expand retrieval when a necessary dependency is missing. Abstain or request clarification when conflicting sources cannot establish authority.
5. **Make maintenance reversible and inspectable.** Separate adding evidence from reorganizing derived indexes. Record revisions, use atomic publication where available, and verify changed projections against required facts. Organization should have a measurable purpose: finding complete evidence, resolving current state, or continuing a task successfully.
6. **Test handoffs with withheld context.** Have a fresh agent read only the proposed filesystem memory and continue a staged task. Include a late correction, an old exception, competing claims, a failed attempt, an unverified plan, and a dependency spread across sessions. Measure preservation of required facts, retrieval of all necessary evidence, correct temporal interpretation, justified abstention, and resumed-task outcomes.

Useful ablations compare raw evidence alone, brief alone, evidence plus brief, and evidence plus navigational indexes under the same reader and tasks. Diagnose a missed requirement at the write, find, interpret, or act stage. Include cases whose wording differs from the stored source and cases where the applicable constraint is not explicitly named by the current request.

## Open questions and evidence limits

The selected studies leave important questions unresolved: how often consolidation introduces unsupported facts over many generations; how well provenance survives reorganizations; how conflicting writes should be reconciled; how omission severity should be weighted; and how a memory detects that its account of current state is stale. Most conversational studies observe question answering rather than durable execution. Filesystem research is promising but does not establish a universally optimal folder taxonomy.

For this project's priority, the strongest defensible direction is a **recoverable evidence layer plus explicitly maintained state and navigational aids**, evaluated with actual fresh-agent continuation. This is a synthesis to test. It is not a claim that storing all history, adopting a graph, or using Markdown guarantees accurate memory.
