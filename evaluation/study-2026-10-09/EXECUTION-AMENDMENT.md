# Infrastructure-only abort and prospective replacement

The first frozen batch rejected any native tool use, including Muse's advertised session-local `write_todos`. Short setup canaries did not use that tool. Longer continuation prompts caused automatic internal to-do updates and a native tool-response round before producing the JSON list request. Of 28 launched native calls, 23 used bookkeeping and five attempted the unadvertised `muse.list`. The host rejected that nonexistent function. The adapter rejected all calls, so **no virtual collection action executed and no case evidence was returned**.

The coordinator was stopped after 25 completed infrastructure-failure receipts. Three further trial directories had been started without final receipts; 58 scheduled jobs had not started. The [aborted results](attempt-1/aborted-results.json), [original freeze](attempt-1/freeze.json) and [exact source snapshots](attempt-1/source-snapshot.json) are retained. No failure was replaced with a selected best retry. The original fixture inputs and gold remain unchanged. Zero accepted calls is not zero provider work: these aborted native requests incurred work that is not part of the replacement trial usage totals.

Before a replacement batch, the boundary is amended to permit **only** that session-local bookkeeping tool. Its actual use is recorded; all other native tools remain rejected. The upstream inventory still contains only `muse.write_todos`, with no filesystem/network/session-history tool. The first request must contain the single explicit prompt; later requests may include the current native tool interaction. They must still use `store:false` and no provider continuation/session association keys. A new rootless process/session/configuration is created for every explicit reader call.

The public runner accepts the same narrow bookkeeping exception. Case inputs, gold, model, low effort, shuffled order, task budgets and scoring rules are unchanged. The prompt states the exception. Freshness applies to unrelated context and previous sessions, not the internal bookkeeping round of the current call. Account-side erasure and the native system prompt remain unproved. A full task-shaped canary is required before the prospective replacement freeze.

This is an infrastructure correction made after rejected transport results, not an outcome-driven filing intervention. Readers had not yet received any virtual source evidence. Both attempts and this limitation must be reported together. There will be no scored retries in the replacement batch.

Before the replacement freeze, trace annotation adds the reader turn for each action and a separate `reader_saw_post_write_check` measurement. A host-observed successful check can occur in the reader's final action batch before the reader sees its output; that is kept distinct from a later reader call that actually receives the receipt. The original complete-task gate remains actual successful post-write execution. Receipt inspection is reported separately rather than silently strengthening the original outcome after the infrastructure abort.

## Second abort and final prospective boundary

The first task-shaped canary tested only one response. The second batch accepted its initial list requests but failed on replay: the native model attempted unavailable `muse.read`/`muse.list` functions despite receiving only the to-do schema. Exact host outputs state `tool unavailable: unknown tool` and identify `write_todos` as the available session tool. No source data was returned by those native attempts. This was native protocol behavior, not a same-call user-replay validation bug.

The second coordinator stopped after **22 completed infrastructure receipts, 25 launched directories, three without final receipts and 61 not started**. Accepted virtual events comprised 22 lists and eight reads of entry/draft/check/obligation material; no original-source full read, search or artifact write was accepted. Partial native requests after coordinator termination do not count as executed collection actions. [All completed receipts](attempt-2/aborted-results.json) and [exact frozen source text](attempt-2/source-snapshot.json) are retained. Default drafts' wrong fields do not show filing mistakes made by readers. Accepted-call token counters omit rejected calls, so aborted attempts' counters cannot represent their full provider usage.

The final boundary treats proven unavailable native calls as recoverable protocol errors, preserving their names/counts. The actual advertised inventory remains only `muse.write_todos`. Accept a non-bookkeeping item only if its native status is failed and its exact output proves unknown-tool unavailability; reject a successful non-bookkeeping action or any other failure. No native read/write request is executed or translated into collection access. Only the reader's subsequent JSON actions are executed under the unchanged virtual allowlists. This distinction avoids confusing a nonexistent tool attempt with a real filesystem operation. It also exposes interoperability overhead rather than concealing it.

Before the third freeze, the prompt explicitly explains that list/read/search/write/check are virtual JSON formats handled after the response. Reasoning effort changes from low to high for the final study, honoring accuracy priority; this is not an experiment on reasoning effort. The same fixtures, gold, conditions, shuffled order, caps and primary scoring rules are retained. A full unscored end-to-end rehearsal must recover source evidence, write, run the check, receive its output in a later call and finish. The final batch has no scored retries; archived aborts are separate, never treated as independent filing observations or removed from execution history.

Fresh native stores and rootless sessions do not prove that the remote account never associates repeated inputs across attempts. That provider-side limitation remains. Neither failed pilot transport nor the final controlled JSON interface is a direct evaluation of the unmodified production CLI or the personal vault.

The high-effort unscored end-to-end rehearsal passed: eight fresh calls, nineteen virtual actions, five original-source reads, a correct artifact, four actual successful structural checks and a later call that received the final receipt. It used Glassmere's source-only family, so that family is setup-exposed rather than a fully withheld test. An earlier first-response canary used Citrine's task text. No canary is counted as a scored success. Other aborted task prompts were also submitted previously; local isolation does not settle remote familiarity with repeated corpus inputs.

Before the final freeze, six simultaneous high-effort transport canaries passed in 9.889 seconds with no native attempt, rate/resource error or changed host-auth/settings/cleanup receipt. The final batch uses six workers to reduce wall time; the two aborted attempts used three. This validates a short burst, not sustained throughput. The worker count is pinned and checked by the final manifest. No filing efficacy comparison is made across the changed infrastructure attempts.
