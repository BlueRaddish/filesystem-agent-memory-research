# Conservative reader concurrency and preserved grid recovery

This operational amendment leaves the original [freeze](freeze.json), its 32 inputs, every scheduled comparison, model, prompt, task, byte budget and outcome rule unchanged. The local grid continues with one worker. Main readers will use the existing supported `--workers 2` option rather than the six workers described in the frozen schedule. All 192 trials remain scheduled; recorded faults and unknown interrupted calls are never replaced or retried. This is a resource choice made before main reader calls, not tuning based on their answers.

One separate development cue-generation attempt returned Windows `0xC000012D`, `STATUS_COMMITMENT_LIMIT`. Nine exit-code-1 causes remain unknown because raw diagnostic bytes were not retained. All ten used the original-query fallback without retry. The status identifies a commitment failure, not which allocation exhausted memory or a provider, authentication or rate-limit cause. [Microsoft status specification](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-erref/596a1078-e883-4972-9bbc-49e60bebca55).

At the bounded October 13 11:57–11:59 UTC observation, the active grid held about 3.58 GB of private commit and 2.19 GB of working set, and system commit headroom was about 1.75 GB. Releasing that process would leave approximately 5.32 GB only if other usage stayed fixed. Timing subsequently loads models again. There is no retained per-call CLI memory measurement, so these observations do not establish that six readers would fail, that two readers are sufficient, or any causal speed comparison. The cap reduces this pool's simultaneous work; other host activity remains uncontrolled.

The original private controller built its stage arguments eagerly and had no cooperative handoff. Its controller and grid belonged to Windows jobs; stopping the controller could not safely assume that its child survived. Recovery therefore terminates only the identity-verified owned grid child with a deliberate nonzero exit. The original controller's existing fail-closed behavior must then halt it before another stage starts. No other session or application is stopped. Debugger thread suspension is not used.

After both owned processes have exited, settled complete-query checkpoints, original controller state/logs and worker-history files are retained. The separate resource freeze records the complete checkpoint names and byte hashes before recovery. Incomplete local ranking work can be recomputed from its query boundary; completed checkpoint rows, including any recorded faults, are reused. The frozen runner still verifies their query/input fingerprints and full census. All diagnostic files, including temporary writes, must be absent at handoff, avoiding loss of an uncheckpointed recorded exception. Incomplete checkpoint temporary files remain privately retained as unfinished work.

[run_resource_capped.py](run_resource_capped.py) checks the original freeze and all its inputs, the amendment/wrapper pins and every preserved checkpoint before restarting the original one-worker grid. It records a new private invocation, preserves the original logs, runs unchanged serial timing and maintenance, launches the unchanged reader with two workers, then runs the frozen analysis. It checks all preserved checkpoint bytes again after collection. Each returned call follows the original durable receipt/pending-marker contract. A failing stage remains failed and incomplete; the wrapper does not automatically retry it.

The resource receipt records the exact original freeze, requested and actual scheduling, preserved checkpoint hashes, stage exits and source pins. Host identities, process IDs, adapter command, raw diagnostic streams and account information stay private. The resource wrapper is a historical recovery procedure requiring the privately retained checkpoints; a clean reproduction can use the original runners and this same documented two-reader cap. Reused grid work is not an isolated latency measurement. The separately specified serial timing block remains the timing evidence.

The small `--self-check` verifies stage ordering, one local worker/two reader workers, original-input and checkpoint mutation rejection, and failure-preserving stage behavior on fake commands and temporary files. It performs no model or provider calls. Full outcome census, byte reconstruction and actual reader-artifact audits remain required after collection.
