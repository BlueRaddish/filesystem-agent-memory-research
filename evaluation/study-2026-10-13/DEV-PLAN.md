## Fixed matched conditions

Use the entire development document collection for every query; never use relevance labels to select distractors or change inputs. Seed `101310`; derived identity hashes use explicit condition namespaces. The original query and declared support alternatives remain matched unless a literal identifier is explicitly transformed as below. Ten conditions (baseline plus nine perturbations):

1. `baseline`: original development records and queries.
2. `iteration_shuffle`: shuffle document dictionary insertion order with a fixed random seed. Existing rankers sort IDs; exact rank/packet digest equality is an implementation boundary check, not evidence of arbitrary file-system invariance.
3. `opaque_ids`: bijectively replace record IDs with unique opaque uppercase/digit strings of the same character length. Remap dictionary keys, typed links/supersedes/incorporates, every boundary-delimited literal ID occurrence in bodies/query/retained textual metadata and aliases, and all gold record references. Equal-width replacements preserve source character offsets. Disclose literal-ID occurrences and transformed positions; assert span text transforms identically. IDs in queries are remapped too, so this tests identifier/tie effects while preserving the declared referent. Body changes can affect lexical cues, and opaque tie order can change zero-score rankings.
4. `path_permutation`: bijectively permute paths and change their directory layouts using identity hashes, retaining body/IDs/edges. The chosen rankers and packers do not use paths; unchanged outcomes are expected and disclose a tautological feature boundary. This does not test navigation/onboarding.
5. `padding_before`: put 4,096 ASCII bytes of segmented, query-absent `devpadzx` noise before each unchanged body.
6. `padding_after`: put the identical noise after each unchanged body.
7. `padding_balanced`: put half before and half after. These three use the same fixed newline separators and identical padding token multiset/byte count. Remap every gold span by the exact prefix length. They preserve every original passage contiguously, but alter body length, lexical normalization, packet feasibility and source placement. Rank order should be position-independent for these bag-based policies; passage selection can still differ. Padding has punctuation/newline boundaries, rather than one giant adjacent sentence.
8. `near_alias_cues`: extract all observable query identifier-like tokens containing digits (ASCII letter/digit/hyphen syntax), generate unique one-character-near strings, and assign these extra aliases cyclically to sorted records. Bodies, queries, record IDs and gold stay unchanged. This is a deliberately query-aware adversarial metadata fixture at constant corpus size; neither gold nor relevance selects the placement, and it is not automatic extraction quality.
9. `near_identifier_records`: add one source record per existing record, with a one-character-near record ID and cyclic near-query identifier alias in an explicitly non-governing reference-marker body. It copies no original facts or support text. Original queries/gold remain unchanged. This also changes collection size, IDF and document-length averages; do not attribute every difference solely to identifier matching.
10. `combined_shuffle_opaque_paths`: apply opaque renaming, path permutation and insertion shuffle together, retaining the same equal-width/query/reference rules. This tests their interaction rather than assuming separately stable changes compose.

All transformations operate on observable document fields and query text; withheld support labels are used only to remap/evaluate source references and offsets. Expected answers, contracts and rationales are neither read nor forwarded. Padding words must be absent from all original development query tokens before execution. No synthetic external corpus is used.

## Fixed methods and endpoints

Three existing stdlib rankers: `body_bm25`, `entity_rrf`, `graph_diffusion`. Rank over the same full observable collection. For both whole-original packing policies, and the passage comparator, keep the first 32 ranked **source-kind** records; derived records can affect ranking but are not packed. This source-only candidate filter is a separately declared development adaptation, applied identically to all arms. It changes the main study's candidate interface and is not a replacement main result.

Three packers at 4,096, 8,192 and 16,384 UTF-8 bytes: existing `whole_record`, existing `sentence_neighbors`, and experimental `nested_whole`. For each query/ranker, `nested_whole` starts with the unchanged greedy whole-record packet at 4 KB. At 8 KB, preserve all existing pieces as an immutable prefix and append omitted candidates in original relevance order if they fit. At 16 KB, retain the 8 KB prefix and repeat. There is no replacement, clipping or reranking; original bodies, exact headers and two-newline separators count. The prototype is hard-coded to these three budget steps and capped at 32 candidates. Preserving early irrelevant choices can cost recovery at larger budgets; no optimality claim is made.

Schedule **10 × 72 × 3 × 3 × 3 = 19,440 packets**. Primary endpoint: any declared sufficient **original-span alternative** is completely exposed by the union of included source-exact character intervals. Secondary: declared whole-original bundle recovery, best declared span fraction, candidate all/any support at 8/16/32 before source filtering and filtered 32, bytes used, byte-bound failures, and oversized original bundles. Merely selecting an ID does not count as span exposure. Measure all actual packet bytes and validate source hashes/text/bounds. Transform spans consistently; original identities can be mapped back for matched comparisons.
