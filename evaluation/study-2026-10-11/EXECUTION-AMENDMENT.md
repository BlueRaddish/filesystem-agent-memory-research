# Execution recovery amendment

The original prospective protocol and all corpus, ranking, packing, model and reader inputs remain pinned by [freeze.json](freeze.json), public commit `eb1ecd575a2d6d1e3bf9e9907a2bd7e3abe52085`. The first tool-managed retrieval process was no longer present when work resumed. Its exit cause and work not persisted to disk are unknown. It left 576 of 18,432 planned comparisons in a running-state file. [interrupted-results.json](interrupted-results.json) preserves those exact bytes; [interruption.json](interruption.json) records the recovery observation. These are execution provenance, not additional independent cases or a finished study.

Before starting recovery, an additional execution manifest pins a resumable orchestration layer and this amendment. It imports the original frozen ranking and packing functions. Each of the 96 unique query strings has an independent score cache in the original implementation, keyed by model/query/document hashes. Recovery groups the frozen shuffled jobs by task while preserving their relative order within each query, including score-batch composition. Four workers use separate scorer instances, each retaining two intra-op CPU threads and the same pinned weights/tokenizers. Completed task chunks are atomically saved outside the public repository and validated against frozen inputs before reuse. Every planned row retains its original global job/ranking/packet ID.

All persisted overlapping outcome fields must agree exactly with the interrupted snapshot before the complete public replacement is accepted. An overlap disagreement is a failure requiring a separately documented investigation, not a license to overwrite results. Resume reuses only verified completed chunks; unknown incomplete task work may be repeated. Deterministic retrieval recomputation is distinct from a retry of a scored reader completion. Reader failures still remain in their fixed denominator and are never silently replaced.

Concurrent collection improves throughput; its wall time and cached ranking receipts are not per-query latency estimates. The separately planned 144 uncached warm timing observations run serially after collection workers finish, with the original two-thread scorer configuration. This separates collection scheduling from the latency comparison. Host activity outside this workload is not controlled or certified.

Timing reuses an already exercised worker's scorers after the pool closes. If a resume loads only completed checkpoints and no exercised instance exists, an explicitly logged development-only warmup initializes each scorer before the timing block. These warmups are excluded from both scored case counts and timing estimates.

A hidden detached host process records logs and advances retrieval, timing and the original reader runner in sequence. This avoids tying execution lifetime to a tool conversation. It changes no retrieval decision rule, family split, byte budget, candidate count, downstream prompt, output gate or selected reader arm. No scored outcome was examined to choose a new parameter or policy. The preserved partial run and recovery provenance remain visible alongside the eventual complete results.
