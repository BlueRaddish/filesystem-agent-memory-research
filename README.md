# Filesystem Agent Memory Research

How should persistent files help an unfamiliar agent recover the context needed to continue work accurately?

This project is a public, source-grounded research review of agent memory, retrieval, personal information management, digital preservation, biological memory, and human learning practices. It prioritizes **preserving important details, resolving changing state, and succeeding after a fresh start**. It studies PARA alongside other organizational approaches without assuming that any folder taxonomy is an optimal memory architecture.

**Initial review cutoff: 2026-10-08 UTC. Pilot execution: 2026-10-09.** This is an AI-assisted structured scoping review with an original fictional continuation pilot: 80 main reader trials, six exploratory onboarding trials, five engineered filesystem traces and four separately reported transport diagnostics. It is not an exhaustive systematic review, a peer-reviewed publication or a validated benchmark. Sources have different publication statuses and review depths, recorded in their catalog entries.

**Expanded study: October 11 Pacific; collection completed October 12 UTC.** All 18,432 packet comparisons, 4,608 rankings, 144 uncached timing observations and 144 fresh-reader trials are recorded over 48 authored family histories and 96 clustered queries. Three switches and six engines have paired comparisons; 36 families are held out. These are repeated measurements, not 18,432 independent cases. The report includes fifteen scientific figure pairs and an execution audit. Separate source catalogs extend the historical review; their entries and supporting URLs are not summed into a unique-paper count.

**Intensive expansion: October 13.** A separately authored bank, 21 retrieval policies, eight source-exact packers, fresh-session navigation and mechanical maintenance tests are prospectively frozen before main scored collection. The [protocol](evaluation/study-2026-10-13/PLAN.md), [analysis specification](evaluation/study-2026-10-13/ANALYSIS-SPEC.md), [bank audit](evaluation/study-2026-10-13/BANK-AUDIT.md) and [research portfolio](evaluation/study-2026-10-13/EXPANSION-RESEARCH.md) distinguish planned comparisons from evidence. An allocation-aborted invocation and a later unknown-exit interruption remain recorded separately. The latest audited recovery baseline preserves 366 complete query checkpoints and 72,468 packets; the system reports a subsequent boot. Main readers and final analysis have not run. Completed supplements and unexecuted protocols are distinguished below.

## Working conclusion

The literature does not establish a universally best folder structure or memory product. A useful direction to test is **recoverable source evidence, a maintained current-state view, and simple navigation that can expand back to the sources**. Correctness also depends on the writer, retriever, reader, and execution environment. An organized collection can still contain an inaccurate summary; a perfect lookup can still select an obsolete rule.

The project distinguishes evidence preservation from retrieval, retrieval from interpretation, and interpretation from action success. Its proposed improvements are hypotheses with failure cases and measurements, rather than an architecture ranking.

In the expanded bank, dependency expansion has the most consistently positive atomic recovery effect. At 144 documents and 8,192 bytes, MiniLM plus expansion/version gating without added headers (`011`) recovers 69/72 authored evidence bundles; all switches enabled recover 61/72. This observed configuration was not separately confirmed on a new bank or in downstream reader trials. At 4,096 bytes, headers reduce the authored-bundle feasibility ceiling from 49/72 to 32/72. Learned branch routing adds computation and establishes no general speed or quality advantage. Main exact value-and-source task completion is 0, 1, 0 and 0 of 24; 21/24 fresh-discovery trials produce no artifact. These outcomes expose packing, reading and completion limits, not a universally best filing system or semantic accuracy estimate.

The expanded blinded LLM review finds source-supported requested values/status in 66 of 123 actual artifacts, including 37 that fail exact answer matching; all 24 diagnostic control artifacts receive full-query support judgments. This exposes substantial scoring-convention sensitivity. The supplement retains every frozen outcome, excludes no-write trials from review rather than hiding them, and claims no human-validated or adjusted accuracy.

The first pilot passes the frozen rubric in **60/80 main trials**. A disclosed source audit accepts **77/80 checked artifacts** after accounting for underspecified output conventions; neither count is a population accuracy estimate. One reader receives all required originals yet retains a superseded setting through successful structural checks. The pilot motivates testing source-version incorporation and correction-specific checks; it does not identify a winning folder taxonomy or justify a production migration.

The biological and human-practice extension examines functions worth translating rather than treating agent files as a replica of a brain. Evidence-checked retrieval probes, distinctive cues, episode-plus-state views, and explicit future obligations are candidate interventions. Human learning benefits and brain-inspired metaphors do not establish that these improve agent continuation; the transfer review specifies comparisons that could test them.

## Check the repository

Python 3.10 or later; repository checks and reader/maintenance runners use the standard library. Scientific figures require Matplotlib. The expanded local scoring runtime additionally uses NumPy, ONNX Runtime and tokenizers; model files stay outside the repository. Its pinned artifacts and execution requirements are documented in the expanded protocol and model runtime.

```sh
python scripts/check_repository.py
python scripts/make_fixture.py /path/to/new-empty-trial-directory
python evaluation/study-2026-10-09/run_study.py selfcheck
python evaluation/study-2026-10-09/replay_maintenance.py --self-check
```

The first command checks catalog structure, citation mappings, local links, publication hygiene, and fixture references. It does not validate every scientific claim or prove absence of sensitive information. The second stages only the fictional agent-facing memory and task prompt for a trial; it excludes evaluator materials. Read the [protocol](evaluation/protocol.md) before using it.

For the October 13 source and boundary checks, run these existing consuming entrypoints from the repository root. They require no model or provider calls:

```sh
python evaluation/study-2026-10-13/bank_check.py --self-check
python evaluation/study-2026-10-13/check_bank_semantics.py
python evaluation/study-2026-10-13/native_index_lab.py --self-check
python evaluation/study-2026-10-13/prepare_reader_review.py --self-check
python evaluation/study-2026-10-13/run_resource_capped.py --self-check
```

These checks cover authored-bank consistency, the completed blind bank comparison, and synthetic query/index/transaction, extraction and resource-recovery boundaries. The native supplement's actual `--stage run` and `--stage aggregate` routes require its verified private development excerpt, manifest and clearance, as specified in its [protocol](evaluation/study-2026-10-13/NATIVE-INDEX-PLAN.md). Actual packet/source reconstruction, retained failures, figure table/hash checks and visual inspection remain separate acceptance gates. The main execution audit requires the complete frozen census and private execution evidence; it cannot pass an interrupted collection. The broad repository scan is root-owned when a blinded or development-only lane must avoid unrelated outcome files. Compile checks, discovery and fixture checks do not establish completion of the real study.
